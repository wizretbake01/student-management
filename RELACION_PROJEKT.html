Përshkrimi i Projektit

Projekti Student Management System është një aplikacion web i ndërtuar me Spring Boot 3.2 dhe Java 17, i cili mundëson menaxhimin e studentëve të universitetit. Aplikacioni ofron funksionalitet të plotë CRUD (Krijo, Lexo, Përditëso, Fshi) për menaxhimin e të dhënave të studentëve, si dhe eksportim të të dhënave në Excel.

Qëllimi i Projektit

Të demonstrohet zbatimi i plotë i një aplikacioni enterprise Java me pipeline CI/CD të plotë, nga zhvillimi lokal deri në deploy automatik në cloud (OpenShift ROSA).

Projekti është i organizuar si Maven multi-module me strukturën e mëposhtme:

Çfarë Bën Secili Modul

📦 model

Si u ndërtua: Klasa Student.java me anotacionet JPA (@Entity, @Table, @Id, @GeneratedValue) dhe Lombok (@Data, @Builder, @NoArgsConstructor).

Shërbeu për: Definimin e strukturës së tabelës students në H2 database. Çdo fushë e klasës u mapua automatikisht si kolonë në databazë nga Hibernate (JPA provider).

📨 dto

Si u ndërtua: Klasa StudentDTO.java si objekt transferimi pa logjikë biznesi, vetëm fushat: id, firstName, lastName, email, studentId, department, status, year.

Shërbeu për: Izolimin e shtresës API nga modeli i brendshëm. REST API pranon dhe kthejn vetëm DTO, duke mbrojtur modelin JPA nga ekspozimi direkt.

⚙️ service

Si u ndërtua: StudentService.java me @Service dhe StudentMapper.java (MapStruct) për konvertimin automatik DTO ↔ Entity. Injektim i StudentRepository (JPA).

Shërbeu për: Gjithë logjikën e biznesit: CRUD operacionet, validimin dhe transformimin e të dhënave. Ndërmjetës mes Controller dhe Databazës.

📊 excel

Si u ndërtua: ExcelExporter.java me Apache POI 5.2.5. Krijon XSSFWorkbook, shton sheet "Studentët", formatohen header-at me bold dhe shkruhen të dhënat rresht pas rreshti.

Shërbeu për: Eksportimin e listës së studentëve si skedar .xlsx për shkarkimin direkt nga browser. Ofron funksionalitet raportimi pa nevojë për softuer të jashtëm.

🌐 web

Si u ndërtua: StudentController.java me @RestController dhe @RequestMapping("/api/students"). Faqja kryesore menaxhohet nga WebController me Thymeleaf template. Porta konfiguruara dinamikisht: server.port=${SERVER_PORT:8080}.

Shërbeu për: Nyja qendrore (entry point) e aplikacionit. Ekspozon REST API-n dhe UI-n HTML5. Inicializon Spring context dhe integron të gjitha modulet e tjera si varësi Maven.

Pse u Zgjodh Secila Teknologji

Teknologjia Si u Integrua Çfarë Shërbeu
Java 17 Installuar lokalisht + konfiguruar në Jenkins si JAVA_HOME Gjuha bazë e projektit. Java 17 është LTS (Long-Term Support) dhe ofron Records, Sealed Classes dhe performancë të përmirësuar ndaj Java 11.
Spring Boot 3.2 Shtuar si parent POM në pom.xml. Auto-konfigurimi aktivizohet automatikisht. Eliminon konfigurimin manual të Spring. Shfaq serverin Tomcat të integruar (embedded), skanimi i anotacioneve dhe dependency injection jashtë kutisë.
Lombok Varësia shtuar, procesori i anotacioneve konfiguruar me maven-compiler-plugin Eliminon getter/setter/constructor boilerplate. @Data gjeneron automatikisht gjithë metodat në compile-time duke mbajtur kodin të pastër.
MapStruct 1.5.5 Interfacë StudentMapper me anotacion @Mapper. MapStruct gjeneron implementimin automatikisht. Konverton Entity → DTO dhe DTO → Entity pa kode manual. Zgjidhja është compile-time (jo reflection) duke qenë 10x më e shpejtë se doMappers të tjerë.
Apache POI 5.2.5 Modul i veçantë excel/. Krijon XSSFWorkbook (xlsx format) dhe shkruan të dhënat. Eksportimi i të dhënave si spreadsheet Excel. Zgjidh nevojën për raportim pa bazë te shërbime të jashtme si Google Sheets.
H2 Database Konfiguruar në application.properties me spring.datasource.url=jdbc:h2:mem:testdb Databazë in-memory që nuk kërkon instalim. Perfekte për demonstrim dhe testing. Të dhënat ruhen gjatë ekzekutimit dhe pastrohen pas rindezjes.
Thymeleaf Shtuar automatikisht nga Spring Boot Starter Web. Templates në src/main/resources/templates/ Gjeneron HTML dinamik server-side. Integrohet direkt me modelet Java dhe ofron sintaksë të thjeshtë (th:each, th:text) pa nevojë për JavaScript framework.
JUnit 5 Klasa test StudentServiceTest.java me @ExtendWith(MockitoExtension.class) dhe @Mock për repository. Verifikoi logjikën e service layer. Tests ekzekutohen automatikisht nga Jenkins në stage "Test" duke siguruar cilësinë e kodit para çdo deploy-i.

Si Funksionon S2I (Source-to-Image)

🔴 Hapi 1: Jenkins dërgon JAR

Jenkins ekzekuton oc start-build student-management --from-file=web/target/web-1.0.0.jar. Ky komand ngarkon fat jar-in (64.90 MiB) direkt tek OpenShift BuildConfig duke shmangur nevojën e pushimit manual.

🟠 Hapi 2: S2I ndërton imazhin Docker

OpenShift merr builder image-in java:17, vendos JAR-in brenda dhe krijon një imazh të ri Docker. Imazhi ruhet automatikisht në OpenShift Internal Registry (image stream student-management:latest).

🟢 Hapi 3: Rolling Update

OpenShift Deployment Config detekton imazhin e ri dhe fillon Rolling Update: ndez pod të ri me versionin e ri, pret që të jetë healthy, pastaj mbyll pod-in e vjetër. Rezulton: zero downtime deployment.

🔵 Hapi 4: Route ekspozon URL

OpenShift Route (oc expose service) krijon URL publike që mapëzon nga port 80/443 te Service port 8080. HAProxy ingress controller merr trafikun dhe e ridrejton tek pod-i aktiv.

Konfigurimi i OpenShift

# Login në cluster oc login https://api.rm3.7wse.p1.openshiftapps.com:6443 # Deploy i parë (S2I build) oc new-app --name=student-management java:17 --binary # Ekspozimi i aplikacionit oc expose service student-management # Trigglerimi nga Jenkins (Build #9) oc start-build student-management --from-dir=. --follow # Verifikimi i deployment oc rollout status deployment/student-management

Fix i Rëndësishëm – Port Conflict

❌ Problemi: Aplikacioni fillimisht kishte server.port=8081 (për të shmangur konfliktin me Jenkins lokal). Por OpenShift Service targetonte portin 8080, duke shkaktuar 503 Service Unavailable.
✅ Zgjidhja: U ndryshua në server.port=${SERVER_PORT:8080} – default 8080 për OpenShift, me mundësi override lokale me SERVER_PORT=8081.
